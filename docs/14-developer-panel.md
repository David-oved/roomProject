# 14 · פאנל המפתח

מסך בתוך האפליקציה הראשית שנראה ונגיש **רק לחשבון אחד** — לא תפקיד,
לא "מנהל על", לא משהו שאפשר להעניק למישהו אחר בלי לערוך קוד ולפרוס
מחדש. שונה מהותית מ[קונסולת הניהול המקומית](../admin/README.md):
זה רץ בתוך ה-bundle הציבורי שכל משתמש מוריד, ומוצג רק כשהאימייל
המחובר תואם.

---

## איך הזיהוי עובד

```
src/lib/developer.ts          DEVELOPER_EMAIL — קבוע מוטבע, מייל אחד
src/components/auth/guards.tsx  RequireDeveloper — מנתב החוצה מי שאינו
database.rules.json           auth.token.email === '<המייל>' — האכיפה
```

**שלוש שכבות, ורק האחרונה היא הגנה אמיתית:**

1. **הצגת הטאב** (`SettingsPage.tsx`) — `isDeveloper(user?.email)`. נוחות
   בלבד: אם false, הפריט פשוט לא ברשימה. אין בזה שום אבטחה.
2. **ניתוב** (`RequireDeveloper`) — מי שמנווט ל-`/developer` ידנית בלי
   להיות המפתח מקבל `<Navigate to="/onboarding" />` בשקט, בלי רמז
   שהמסך בכלל קיים.
3. **Security Rules** — ההגנה היחידה שבאמת מונעת קריאת נתונים. משווה
   `auth.token.email` (claim חתום על ידי Firebase בתוך ה-ID token,
   לא ניתן לזיוף בלי הסיסמה בפועל של החשבון) לקבוע מוטבע. גם אם מישהו
   יפתח את ה-URL ידנית עם DevTools פתוח, השרת דוחה אותו לפני שורת מידע
   אחת.

**מייל ולא uid**, בכוונה: `auth.token.email` הוא מה שהמפתח בעצמו יכול
לזהות ולאמת (רואה אותו בהגדרות ← חשבון), בעוד `uid` הוא מזהה אטום.
כדי לעדכן את הזהות המורשית, משנים את הקבוע בשלושת המקומות (כן, גם
בכללים) ומפרסים.

## מה נחשף — ומה לא

היקף מכוון וצר, "חלק ממידע הדשבורד" ולא כולו:

| נחשף | לא נחשף |
|---|---|
| `roomCodes` — כל קודי החדרים במערכת | קניות, מאזנים, סגירות חשבון |
| `rooms/{code}/metadata` — שם, תיאור, מנהל, תאריך יצירה, ארכוב | צ'אט, הודעות, שידורים |
| `rooms/{code}/members` — מי בכל חדר, תפקיד, סטטוס, תאריך הצטרפות | מטלות, מוצרים |
| `users` — כל המשתמשים: שם, מייל, תאריך הרשמה, פעילות אחרונה | בקשות הצטרפות ממתינות |

**קריאה בלבד.** אין `.write` חדש בשום מקום — הטאב מציג, לא עורך.
פעולות ניהול (השעיה, ארכוב, מענה למשוב) נשארות בקונסולת הניהול
הנפרדת, שרצה רק מקומית עם Admin SDK מלא.

### למה זה בטוח שהיקף הקריאה מוגבל בפועל

הכללים מוסיפים `.read` בדיוק בצמתים `rooms/{code}/metadata` ו-
`rooms/{code}/members` — **לא** ב-`rooms/{code}` עצמו וגם לא ב-`rooms`
עצמו. ב-Realtime Database, מתן `.read` לצומת ילד אינו "יורש" אליו את
`.write` של ההורה ואינו פותח קריאה לילדים *אחרים* של אותו הורה
(purchases, chat וכו') — קריאה חייבת להיות מכוונת בדיוק לנתיב שיש לו
הרשאה. זו בחירה מכוונת: אפילו קריאה גולמית מה-console של הדפדפן לא
יכולה לחשוף יותר ממה שהטבלה למעלה מפרטת, בלי לגעת שוב בקובץ הכללים.

## מבנה המסך

`src/pages/DeveloperPage.tsx`, נטען דרך `src/hooks/useDeveloperOverview.ts`.

- **טעינה חד-פעמית** (`get`, לא `onValue`) עם כפתור רענון — לא מנוי
  חי. זה כלי לעיון מזדמן של אדם אחד, לא מסך שצריך להתעדכן בזמן אמת;
  מנוי חי היה פותח חיבור לכל חדר קיים בבת אחת בלי שום צורך.
- **טאב חדרים** — כרטיס לכל חדר (שם, קוד, מנהל, מספר חברים, תאריך
  יצירה, תג ארכיון), נפתח לרשימת חברים מלאה.
- **טאב משתמשים** — כל משתמש רשום, כולל מי שלא הצטרף לאף חדר, עם
  badge לכל חברות (שם החדר + תפקיד + סטטוס). ממוין לפי פעילות אחרונה.

```bash

npm run emu:seed     # טרמינל 2 — נתוני הדגמה
npx vitest run tests/rules   # (מול אמולטור פעיל)
```

לבדיקה ידנית מול האמולטור: יוצרים משתמש עם המייל מ-`DEVELOPER_EMAIL`
(Firebase Auth Emulator, כל סיסמה עובדת), מצרפים אותו לחדר קיים כדי
שיוכל להגיע ל-הגדרות, ונכנסים דרך מסך ההתחברות הרגיל.
