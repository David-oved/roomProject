# 10 · מנגנון הגרסאות והעדכון האוטומטי

מסמך זה מתאר את המנגנון שמבטיח שכל משתמש מריץ תמיד את הגרסה העדכנית — גם כשהאפליקציה מותקנת אצלו כ-PWA על מסך הבית.

---

## 1. הבעיה

משתמש שמתקין PWA למסך הבית **לא מקבל עדכונים אוטומטית**. שלוש שכבות שונות שומרות את הקוד הישן:

| שכבה | מה נשמר | לכמה זמן |
|------|---------|-----------|
| Service Worker (Workbox) | כל קבצי ה-JS/CSS/HTML | **עד שהמפתח מכריח רענון** |
| Cache Storage | אותם קבצים | לנצח |
| מטמון ה-HTTP של GitHub Pages | `index.html` | 10 דקות |

התוצאה בלי טיפול: מעלים תיקון קריטי לשרת, והמשתמשים ממשיכים להריץ את הגרסה השבורה — לפעמים ימים.

**ומכיוון שהמשתמשים לא יכולים לשנות קבצי קוד במכשיר שלהם**, אין להם שום דרך לתקן את זה בעצמם.

---

## 2. הפתרון — קובץ יחיד

```
┌──────────────────────────────────────────────────────────────┐
│  public/version.json  ← מקור האמת היחיד                       │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ { "version": "1.0.1",                                  │  │
│  │   "forceUpdate": false,                                │  │
│  │   "title": "תיקון חלוקת הוצאות",                        │  │
│  │   "notes": ["…"] }                                     │  │
│  └────────────────────────────────────────────────────────┘  │
└───────────┬──────────────────────────────────┬───────────────┘
            │ נקרא בזמן build                   │ נקרא בזמן ריצה
            ▼                                  ▼  (fetch, no-store)
   __APP_VERSION__ = "1.0.1"          המניפסט שעל השרת
            │                                  │
            └──────────► השוואה ◄──────────────┘
                            │
              ┌─────────────┴──────────────┐
              ▼                            ▼
        זהה → אין עדכון          שונה → יש גרסה חדשה
                                          │
                            ┌─────────────┴─────────────┐
                            ▼                           ▼
                   forceUpdate: false          forceUpdate: true
                   באנר "עדכן עכשיו"           עדכון מיידי, בלי לשאול
```

**המפתח לכל זה:** אותו קובץ נקרא **גם ב-build וגם בזמן ריצה**. לכן אי אפשר שהגרסה שרצה אצל המשתמש והגרסה שעל השרת ייצאו מסנכרון בלי שנדע.

## 3. מבנה `version.json`

```jsonc
{
  "version": "1.0.1",              // חובה. פורמט semver
  "releasedAt": "2026-08-18",      // להצגה בלבד
  "forceUpdate": false,            // ‼️ true = עדכון מיידי בלי לשאול
  "title": "תיקון חלוקת הוצאות",    // כותרת הבאנר
  "notes": [                       // עד 3 שורות מוצגות
    "תוקן חישוב חלוקה שווה",
    "שיפור מהירות הטעינה"
  ]
}
```

| שדה | חובה | תפקיד |
|-----|:----:|-------|
| `version` | ✅ | ההשוואה מתבצעת מולו |
| `forceUpdate` | ✅ | `true` = כפייה, `false` = הצעה |
| `title` | ➖ | כותרת הבאנר |
| `notes` | ➖ | רשימת שינויים |
| `releasedAt` | ➖ | תאריך |

## 4. מתי נבדק עדכון

`UpdateProvider` בודק בארבע נקודות — כדי לתפוס גם משתמשי PWA, שאצלם האפליקציה כמעט לא נסגרת אלא רק עוברת לרקע:

| טריגר | למה |
|-------|-----|
| **טעינת האפליקציה** | הכניסה הרגילה |
| **`visibilitychange` → visible** | ⭐ החזרה מרקע — כך "נכנס מחדש" משתמש PWA |
| **אירוע `online`** | הרשת חזרה |
| **כל 15 דקות** | סשנים ארוכים |

הבדיקה מדלגת אוטומטית כשאין רשת.

---

## 5. מה עושה "עדכון תוכנה"

`performUpdate()` ב-`src/lib/version.ts` — שלושה שלבים:

```
1. ביטול רישום כל ה-Service Workers   →  אין מי שיגיש קוד ישן
2. מחיקת כל ה-Cache Storage           →  אין קבצים שמורים
3. טעינה מחדש עם ?_v=<timestamp>      →  עוקף גם את מטמון ה-HTML של GitHub Pages
```

**התוצאה: כל הקבצים יורדים מחדש מהשרת.**

> **מה שלא נמחק, בכוונה:** `IndexedDB`. שם יושב מטמון הקריאה של נתוני החדר — זה מידע של המשתמש, לא קוד אפליקציה. מחיקתו הייתה גורמת למשתמש להיפתח למסך ריק אם אין לו רשת מיד אחרי העדכון.

## 6. שני מצבי העדכון

### 🔵 `forceUpdate: false` — עדכון רגיל

כרטיס שצף מעל הניווט התחתון:

```
┌────────────────────────────────────────┐
│  ✨  תיקון חלוקת הוצאות                 │
│      1.0.0 ← 1.0.1                     │
│      • תוקן חישוב חלוקה שווה            │
│      • שיפור מהירות הטעינה             │
│                                        │
│  [   עדכן עכשיו   ]      [ אחר כך ]    │
└────────────────────────────────────────┘
```

"אחר כך" מסתיר עד הכניסה הבאה. לא נועל, לא חוסם.

### 🔴 `forceUpdate: true` — עדכון כפוי

בלי שאלה, בלי כפתורים. מסך מלא חוסם:

```
┌────────────────────────────────────────┐
│                  🔄                    │
│        מעדכן את האפליקציה…             │
│                                        │
│   מוריד מחדש את כל הקבצים. זה ייקח     │
│   כמה שניות ואז האפליקציה תיפתח מחדש.  │
└────────────────────────────────────────┘
```

**מתי להשתמש:** תיקון באג שמשחית נתונים, פרצת אבטחה, שינוי במבנה הנתונים שהגרסה הישנה לא מכירה. **לא** לשינויי עיצוב.

## 7. 🛡️ שומר הלולאה — החלק הכי חשוב

זה תרחיש הכשל שהורס אפליקציות עם עדכון כפוי:

```
1. מעדכנים ל-version.json ל-1.0.1  ✅
2. שוכחים לבנות ולפרוס מחדש        ❌
3. משתמש נכנס → השרת אומר 1.0.1, הקוד אומר 1.0.0
4. forceUpdate → רענון → שוב 1.0.0 ≠ 1.0.1 → רענון → …
   → 🔁 לולאה אינסופית. המשתמש לכוד. לא יכול לעשות כלום.
```

**שתי הגנות:**

**א. הגנת זמן ריצה** — אחרי **2** עדכונים כפויים באותו סשן, האפליקציה מפסיקה לכפות ומציגה באנר רגיל עם הסבר:

```ts
// src/lib/version.ts
const MAX_FORCE_ATTEMPTS = 2;   // נספר ב-sessionStorage
```

**ב. הגנת CI** — `scripts/check-version.mjs` רץ בכל build ונכשל אם `version.json` ו-`package.json` לא מסכימים. זה תופס את הטעות **לפני** שהיא מגיעה למשתמשים.

## 8. איך משחררים גרסה

```bash
# עדכון רגיל
npm run release -- 1.0.1 "תיקון חלוקת הוצאות"

# העלאה אוטומטית של מספר הגרסה
npm run release -- patch          # 1.0.0 → 1.0.1
npm run release -- minor          # 1.0.1 → 1.1.0
npm run release -- major          # 1.1.0 → 2.0.0

# 🔴 עדכון כפוי
npm run release -- 1.0.2 "תיקון קריטי" --force

# עם רשימת שינויים
npm run release -- 1.1.0 "פיצ'רים חדשים" "סגירת חשבון" "דוח חודשי"
```

הסקריפט מעדכן **גם** את `public/version.json` **וגם** את `package.json` — כך שהם לעולם לא נפרדים.

ואז:

```bash
git add -A
git commit -m "release: 1.0.1"
git push
```

ה-GitHub Action בונה ופורס אוטומטית. תוך 2–3 דקות כל המשתמשים יקבלו את ההתראה.

- [ ] `node scripts/check-version.mjs` עובר

- [ ] `notes` בעברית וברורים למשתמש קצה
