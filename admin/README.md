# 🛡️ קונסולת המנהל — RoomMate Admin Console

אפליקציית דסקטופ שרצה **על המחשב של מנהל התוכנה בלבד**. היא נותנת תמונת
מצב מלאה על המערכת — מי עושה מה, באיזה חדר, מה נשבר, ומה המשתמשים אומרים
— ומאפשרת לפעול: לאשר, להתערב, לשלוח הודעה, לייצא דוח.

```
npm run admin:shortcut   # פעם אחת: מתקין קיצור על שולחן העבודה
```

מכאן והלאה הקונסולה נפתחת ב**שני קליקים**: לחיצה כפולה על הקיצור →
דפדפן שנפתח על קונסולה כבר מחוברת. אין טרמינל, אין פקודה, אין טוקן
להדביק. מה שקורה מאחורי הקלעים מתואר ב„כניסה בשני קליקים” למטה.

---

## למה זה לא חלק מהאפליקציה

באפליקציה הראשית, כל משתמש רואה רק את החדרים שלו — וכך גם צריך להיות.
מה שמונע ממנו לראות יותר הוא Security Rules, ולא הממשק. קונסולה שרצה
בדפדפן של משתמש הייתה חייבת הרשאת קריאה גורפת לכל העץ, וכל דלת כזו היא
דלת שאפשר לפרוץ.

לכן הקונסולה בנויה אחרת:

```
┌──────────────────────────┐        ┌─────────────────────────┐
│  ממשק (React, 127.0.0.1) │ ⇄ API  │ שרת מקומי (Node)        │
└──────────────────────────┘        │  firebase-admin SDK     │
                                    └───────────┬─────────────┘
                                                │ עוקף Rules
                                       ┌────────▼────────┐
                                       │  Firebase RTDB  │
                                       └─────────────────┘
```

מפתח ה-service account לעולם לא עוזב את המחשב שלי, והדפדפן מדבר רק עם
`127.0.0.1`.

## כניסה בשני קליקים

```bash
npm run admin:shortcut
```

יוצר על שולחן העבודה פריט בשם „RoomMate Admin” — חבילת `.app` ב-macOS,
קיצור ב-Windows, ו-`.desktop` בלינוקס (שנוסף גם לתפריט האפליקציות).

הלחיצה עליו מריצה את `admin/launch.mjs`, שעושה שלושה דברים:

1. בודק אם השרת כבר חי; אם לא — מרים אותו כתהליך מנותק, בלי חלון
   טרמינל שנשאר פתוח. הפלט נכתב ל-`admin/.data/launch.log`.
2. מנפיק **כרטיס כניסה חד-פעמי** בן 60 שניות.
3. פותח את הדפדפן על `/enter?ticket=…`, שפודה את הכרטיס לסשן ומעביר
   לקונסולה.

בפעם הראשונה הממשק נבנה (`admin:build`) ולכן הפתיחה איטית יותר. מכאן
והלאה השרת מגיש את הגרסה הבנויה — בלי Vite, בלי תהליך שני.

> ‼️ הקיצור צורב לתוכו את הנתיב המלא ל-node. פריט שנפתח מ-Finder או
> מסייר הקבצים אינו רואה את ה-PATH של הטרמינל, ומי שהתקין node דרך
> nvm היה מקבל „command not found” בלי שום רמז למה. אם החלפתם גרסת
> node — הריצו `npm run admin:shortcut` שוב.

### פרויקט שיושב בתיקייה מסונכרנת (OneDrive / Dropbox / Drive)

‼️ **שימו לב.** `admin/.data/token` הוא אישור גישה, ו-
`admin/service-account.json` עוקף את כל ה-Security Rules. תיקייה
מסונכרנת מעלה את שניהם לענן — כלומר הסוד שאמור לא לעזוב את המחשב,
עוזב אותו בשקט. `npm run admin:shortcut` מזהה את המצב ומתריע.

הפתרון: להוציא את הסודות מהסנכרון. **התוכן** של `admin/.env.local`
(קובץ, לא פקודות):

```ini
ADMIN_DATA_DIR=C:\RoomMateAdmin\data
ADMIN_SERVICE_ACCOUNT=C:\RoomMateAdmin\service-account.json
```

ב-PowerShell, ליצירה בפקודה אחת:

```powershell
New-Item -ItemType Directory -Force -Path C:\RoomMateAdmin\data | Out-Null
@"
ADMIN_DATA_DIR=C:\RoomMateAdmin\data
ADMIN_SERVICE_ACCOUNT=C:\RoomMateAdmin\service-account.json
"@ | Set-Content admin\.env.local -Encoding ASCII
```

> ‼️ `-Encoding ASCII` ולא `UTF8`: PowerShell 5.1 מוסיף BOM, שנדבק
> לשם המפתח הראשון והופך אותו ללא-מזוהה. הטוען חותך BOM מאז, אבל
> ASCII חוסך את השאלה (הערכים כאן הם נתיבים באנגלית ממילא).

אחרי המעבר: מחקו את `admin\.data` הישן. ואם `service-account.json`
כבר שהה בתיקייה המסונכרנת — הוא היה בענן. הנכון הוא **לבטל אותו
ב-Firebase Console ולהנפיק מפתח חדש**, לא רק להזיז את הקובץ.

(או פשוט להחזיק את הפרויקט מחוץ לתיקייה המסונכרנת.)

### פרטי Windows

- הקיצור על שולחן העבודה מצביע על `admin\launch.cmd`, שנוצר בהתקנה
  ומוצא את הפרויקט דרך `%~dp0`. ‼️ הנתיב **לא** נכתב כטקסט בתוך קובץ
  האצווה בכוונה: `cmd.exe` קורא `.cmd` בקידוד ה-OEM של המסוף ולא
  ב-UTF-8, ונתיב עברי (למשל תחת „שולחן העבודה”) היה נשבר.
- שולחן העבודה מאותר דרך `[Environment]::GetFolderPath('Desktop')` —
  התיקייה מתורגמת לעברית ולעיתים מועברת ל-OneDrive, ולכן `~/Desktop`
  אינו הימור טוב.
- אם PowerShell חסום במדיניות הארגון, ההתקנה תדפיס את הנתיב ל-
  `admin\launch.cmd` כדי שתיצרו לו קיצור ידנית. הקובץ עצמו עובד.

## הרצה מהטרמינל

### מצב הדגמה (ברירת מחדל, בלי חיבור לייצור)

```bash
npm run admin
```

בלי `service-account.json` הקונסולה עולה על נתוני הדגמה מלאים: חמישה
חדרים (בריא / בסיכון / נטוש), 14 משתמשים, קניות, מטלות, משוב והודעות.
כל הפעולות עובדות ונשמרות מקומית ב-`admin/.data/demo-db.json`.

### מול האמולטור המקומי (מומלץ לפיתוח)

נתונים אמיתיים של האפליקציה, בלי להחזיק מפתח ייצור על המחשב:

```bash
npm run emu                                  # טרמינל 1 — אמולטורים
npm run emu:seed                             # טרמינל 2 — זריעת נתונים
FIREBASE_DATABASE_EMULATOR_HOST=127.0.0.1:9000 \
GCLOUD_PROJECT=<project-id> npm run admin    # טרמינל 3 — הקונסולה
```

הקונסולה תעלה במצב חי ותציג "אמולטור מקומי" במסך המערכת. כך אפשר לבדוק
פעולות שכותבות לנתונים — אישור קנייה, מענה למשוב, ארכוב חדר — ולראות
את התוצאה באפליקציה עצמה, בלי סיכון.

### מצב חי (נתוני ייצור)

1. Firebase Console → ⚙️ Project settings → Service accounts →
   **Generate new private key**.
2. שמרו את הקובץ בשם `admin/service-account.json`
   (או הגדירו `ADMIN_SERVICE_ACCOUNT=/path/to/key.json`).
3. ודאו ש-`VITE_FB_DATABASE_URL` מוגדר ב-`.env.local` שבשורש.
4. `npm run admin`

> ‼️ `service-account.json` הוא **סוד אמיתי** — בניגוד ל-apiKey של הלקוח,
> הוא עוקף את כל ה-Security Rules. הוא נמצא ב-`.gitignore`, ואסור לו
> להיכנס ל-git, ל-Drive או ל-Slack.

### משתני סביבה

| משתנה | ברירת מחדל | תפקיד |
|---|---|---|
| `ADMIN_PORT` | `5190` | פורט שרת ה-API המקומי |
| `ADMIN_WEB_PORT` | `5199` | פורט שרת הפיתוח של הממשק |
| `ADMIN_SERVICE_ACCOUNT` | `admin/service-account.json` | נתיב למפתח |
| `ADMIN_DATABASE_URL` | `VITE_FB_DATABASE_URL` | כתובת ה-RTDB |
| `ADMIN_SESSION_HOURS` | `12` | תוחלת חיים מוחלטת של סשן |
| `ADMIN_IDLE_MINUTES` | `30` | נעילה אחרי חוסר פעילות של המשתמש |
| `ADMIN_AUTOSTOP_MINUTES` | `60` | כיבוי השרת אחרי חוסר פעילות (`0` מבטל) |
| `ADMIN_DATA_DIR` | `admin/.data` | איפה יושבים הטוקן, הלוגים ומטמון ההדגמה |

## "רק אני" — שכבות הגישה

הקונסולה מדברת עם בסיס הנתונים דרך Admin SDK, כלומר **עוקפת את כל
ה-Security Rules**. מי שנכנס אליה יכול הכול. לכן הגישה נשענת על חמש
שכבות, ולא על סיסמה אחת:

| # | שכבה | מה היא מונעת |
|---|---|---|
| 1 | האזנה ל-`127.0.0.1` בלבד | גישה מהרשת — גם לא מאותו Wi-Fi |
| 2 | בדיקת מקור + `Host` | DNS rebinding: דומיין זדוני שמצביע ללולאה המקומית |
| 3 | `Sec-Fetch-Site` / `Origin` | אתר שפתוח בטאב אחר שמנסה לדבר עם הקונסולה |
| 4 | סשן דו-חלקי, קצוב בזמן | אישור קבוע ששוכב בדפדפן |
| 5 | טוקן ראשי (600) לשחזור בלבד | טוקן שדלף והופך לכניסה לצמיתות |

### הסשן הוא שני חצאים, לא טוקן

אחרי פדיון הכרטיס נוצרים שני ערכים שחייבים להגיע **יחד** בכל בקשה:

- **מזהה הסשן** — בעוגייה `HttpOnly` + `SameSite=Strict`. ה-JavaScript
  של הממשק אינו יכול לקרוא אותה.
- **סוד הסשן** — ב-`localStorage`, נשלח בכותרת `x-admin-session`.

‼️ החלוקה הזאת אינה קישוט. עוגיות ב-localhost **אינן מופרדות לפי
פורט**: כל שרת מקומי אחר שגולשים אליו באותו דפדפן (`127.0.0.1:3000` של
פרויקט אחר) מקבל את העוגייה שלנו בבקשה ויכול לשחזר אותה. `localStorage`
לעומת זאת כן מופרד לפי פורט. וההפך: מה שיושב ב-`localStorage` נגיש
ל-JavaScript, ולכן חצי שאינו נגיש לו הופך גניבה כזאת לחסרת תועלת.
כל חצי לבדו — לא שווה כלום.

### מה שפג מעצמו

| מנגנון | ברירת מחדל | למה |
|---|---|---|
| כרטיס כניסה | 60 שניות, שימוש יחיד | הוא נוסע ב-URL |
| סשן — חוסר פעילות | 30 דקות | מחשב שנעזב פתוח |
| סשן — זמן מוחלט | 12 שעות | סשן ששכחו ממנו |
| כיבוי השרת | 60 דקות ללא פעילות | מפתח הייצור לא נשאר בזיכרון ימים |
| נעילה אחרי כישלונות | 8 ניסיונות → 5 דקות | ניחוש טוקן |

שעון חוסר-הפעילות נמדד לפי **פעולה אמיתית של המשתמש** (לחיצה, מקש) ולא
לפי בקשות רשת: טאב פתוח ברקע ממשיך לדבר עם השרת, ולכן ספירה לפי בקשות
הייתה מבטלת בדיוק את מה שהמנגנון נועד לתפוס. גם חיבור ה-SSE נבדק
תקופתית מול הסשן — אחרת מסך שננעל היה ממשיך לקבל את הזרם החי ברקע.

בסרגל העליון יש כפתור **🔒 נעילה** שסוגר את הסשן בשרת מיד. הפעלה מחדש
של השרת מנתקת ממילא כל סשן קיים — הם חיים בזיכרון בלבד.

### הטוקן הראשי

נוצר פעם אחת ונשמר ב-`admin/.data/token` (הרשאות 600, או תחת
`ADMIN_DATA_DIR`). הוא משמש לשני דברים בלבד: המשגר מנפיק איתו כרטיסים,
וכלים שאינם דפדפן (curl, סקריפט) מזדהים איתו.

‼️ השרת מדפיס בעלייה את **הנתיב** לקובץ ולא את הערך. כשהמשגר מפעיל
אותו, הפלט נכתב ללוג — ולוג שמכיל אישור גישה קבוע הוא בדיוק הדליפה
שכל המנגנון כאן נועד למנוע.

‼️ **מדפדפן הוא נדחה.** כל עוד טוקן קבוע מספיק כדי לגלוש, מספיק שהוא
ידלוף פעם אחת — היסטוריית פקודות, לוג, צילום מסך של הטרמינל — כדי לתת
גישה לצמיתות. הדבקת הטוקן במסך הנעילה עוברת דרך `/api/session/exchange`,
שמחליף אותו בסשן קצוב; הטוקן עצמו לעולם אינו נשמר בדפדפן.

## החלטות שכדאי להכיר

### הפיד נגזר מהנתונים, לא מיומן אירועים
RTDB מחזיק **מצב**, לא היסטוריה. כל אירוע בפיד נגזר מחותמת זמן של רשומה
קיימת (`item.reportedAt`, `purchase.createdAt`, `member.joinedAt`…).
היתרון: אי אפשר לאבד אירוע ואי אפשר לזייף אחד — מה שרואים הוא בדיוק מה
שקיים בבסיס הנתונים. המחיר: אין אירועי "צפה במסך", ומחיקה של רשומה מוחקת
גם את האירוע שלה.

### "אורך סשן" הוא הערכה — והממשק אומר את זה
אין SDK אנליטיקה ואין מעקב בדפדפן של המשתמשים. סשן מוגדר כאשכול פעולות
של אותו משתמש עם פער קטן מ-30 דקות. בכל מקום שבו המספר מוצג הוא מסומן
כהערכה, כי מספר שמתחזה למדויק גרוע ממספר שמודה שהוא לא.

### תוכן שיחות מטושטש עד לחיצה
הודעות צ׳אט של שותפים מופיעות בפיד כ"כתב הודעה", והתוכן מטושטש. לחיצה
מפורשת חושפת אותו. "לדעת שדובר" ו"לקרוא מה נאמר" הן שתי החלטות שונות,
וכלי שמערבב ביניהן הופך קריאת שיחות פרטיות לדבר שקורה בהיסח דעת.

### שום פעולה לא מוחקת נתונים
- **איפוס מאזנים** מסמן קניות מאושרות כ-`settled`. הקניות נשארות ביומן.
- **ארכוב חדר** מסמן `metadata/archivedAt`. שום ענף לא נמחק.
- לפני כל פעולה הרסנית נשמר גיבוי מלא של הצומת תחת
  `adminConsole/backups`, וכל פעולה נרשמת ב-`adminConsole/auditLog`
  (מי, מתי, על מה, ומה היה הערך הקודם).

### למה יש כאן עותק של מנוע הכספים
`admin/server/money.mjs` הוא עותק סמנטי של `src/lib/money.ts`, ולא ייבוא.
הקונסולה היא כלי **ניטור**: אם מחר תשתנה שיטת החישוב באפליקציה, אני רוצה
שהקונסולה תמשיך לחשב לפי הכלל שאני מכיר — ושהפער יתגלה, במקום שיוסתר על
ידי שימוש חוזר באותו קוד. הבדיקות ב-`tests/admin` נועלות את ההתנהגות.

### התראה נעלמת מעצמה
כל התראה נגזרת מהמצב הנוכחי. כשהבעיה נפתרת, ההתראה נעלמת בלי "סימון
כטופל". מה שנשמר הוא רק מתי ראיתי אותה לראשונה ואם ביטלתי אותה — כדי
ש"חדש מאז שיצאתי" יהיה מידע אמין.

## מבנה

```
admin/
├─ launch.mjs             משגר שני-הקליקים: שרת מנותק + כרטיס + דפדפן
├─ launch.cmd             נוצר בהתקנה ב-Windows (לא ב-git)
├─ start.mjs              משגר פיתוח: שרת + Vite + פתיחת דפדפן
├─ vite.config.ts         בנייה נפרדת לגמרי מהאפליקציה (בלי PWA)
├─ server/
│  ├─ index.mjs           שרת HTTP, SSE, כניסה, הגשת סטטי
│  ├─ auth.mjs            שער הגישה: מקור, Host, עוגייה, טוקן
│  ├─ session.mjs         סשנים, כרטיסים חד-פעמיים, נעילה
│  ├─ config.mjs          סביבה, מצב חי/הדגמה
│  ├─ db.mjs              שכבת נתונים: Admin SDK או זיכרון
│  ├─ seed.mjs            עולם ההדגמה
│  ├─ state.mjs           מטמון של כל הנגזרות + הודעה על שינוי
│  ├─ world.mjs           מודל העולם (משתמשים, חדרים, כספים)
│  ├─ activity.mjs        גזירת אירועים, פיד, צירי זמן
│  ├─ insights.mjs        התנהגות משתמשים ופלחים
│  ├─ roomHealth.mjs      ציון בריאות וזיהוי בעיות
│  ├─ alerts.mjs          טריגרים, שעות שקט
│  ├─ feedback.mjs        מיזוג משוב + מצב טיפול
│  ├─ messaging.mjs       קהלים, מעקב מסירה, שיחות
│  ├─ reports.mjs         דוחות וייצוא
│  ├─ actions.mjs         כל הכתיבות + יומן ביקורת + גיבויים
│  └─ api.mjs             טבלת הנתיבים
└─ web/src/               ממשק React (ראו docs/13-admin-console.md)
```

והקיצור עצמו נוצר ב-`scripts/install-admin-shortcut.mjs`.

חוזה הנתונים מול אפליקציית המשתמשים מתועד ב-`docs/13-admin-console.md`.
